# 射频与合规提示

> 本文是**提示**，不是使用限制。代码不会禁止你修改射频参数或启用 WiFi/蓝牙；
> 但你需要为自己设备的合规性负责。
>
> 本文不构成法律意见，也不替代 SRRC / CE / FCC 等认证。

---

## 1. 默认配置（`guachat_dev`）

| 项目 | 默认值 |
| --- | --- |
| 模块 | E28-2G4M20S（SX1280） |
| 频段 | 2402–2482 MHz |
| 默认频率 | 2405.0 MHz |
| 调制 | LoRa，SF10，BW 812.5 kHz，CR 4/5 |
| 发射功率 | 默认/推荐 **+7 dBm**；模块硬件上限 **+20 dBm** |
| 天线 | 板载 PCB 天线，约 +2 dBi |
| 估算 EIRP | 约 **+9 dBm（≈7.9 mW）** |
| SPI | SPI3（不得改回 SPI2，会干扰屏幕） |

代码边界：

- `src/bsp/bsp_pins.h`：`BSP_LORA_FREQ_MIN_MHZ` / `MAX_MHZ`、
  `BSP_LORA_POWER_RECOMMENDED_DBM`（默认/推荐 7 dBm）、
  `BSP_LORA_POWER_MAX_DBM`（模块硬件上限 20 dBm）
- `src/SX1280/RadioConfig.h`：驱动层频率与功率边界
- `bsp_radio_set_params()`：应用层下发参数；频率与 20 dBm 硬件上限仍会钳位，
  但高于 7 dBm 不会阻止，只在串口打印风险提示

## 2. 默认值为什么保守

开发基线采用较保守的出厂配置：

- LoRa 模块与板载天线固定，不预留外接天线接口（ESP32 的 WiFi / BLE 天线见第 4 节）；
- 功率默认/推荐 7 dBm，EIRP 控制在约 9 dBm；可以上调到模块硬件上限 20 dBm，
  但高于 7 dBm 时只提示风险；
- 频率限制在 2402–2482 MHz；
- 固件默认不启用 WiFi / 蓝牙；
- 不提供越过驱动边界的调整入口。

在符合《微功率（短距离）无线电设备目录和技术要求》（工信部 2019 年第 52 号公告）
相关条件时，这类 2.4 GHz 微功率设备可按目录要求使用。具体适用性以现行法规和
设备实际参数为准。

---

## 3. 你可以改什么

本仓库用于学习、实验和自用。**以下改动不被代码禁止**：

- 修改 LoRa 频率、扩频因子、带宽、功率（在驱动边界内）
- 更换天线、增加功放、改用外接天线
- 启用 WiFi、蓝牙、ESP-NOW、Web 服务器等 2.4 GHz 功能
- 修改分区表、增加 OTA、改变启动流程

但请注意：

1. **驱动边界不是法律边界**。改 `RadioConfig.h` 或换硬件后，EIRP 可能超过
   微功率设备限值，默认的豁免条件可能不再适用。
2. **WiFi/蓝牙会改变射频特性**。发射功率、占空比、天线共用都可能影响合规性。
3. **天线是关键**。高增益天线会直接提高 EIRP；拆换天线后默认的合规假设失效。
4. **销售与自用不同**。自用实验由制作者承担；对外销售通常需要相应认证。
5. **航空、医疗、应急等场景**有额外限制，请自行确认。

## 4. 如何启用 WiFi / 蓝牙

开发基线**不在运行时初始化** WiFi / 蓝牙，但不要依赖 `platformio.ini` 里的
`-DCONFIG_BT_*` 标志做隔离：Arduino-ESP32 的预编译 `sdkconfig.h` 仍会把
`CONFIG_BT_ENABLED` 定义为 1，这些应用层宏不会裁掉框架里的蓝牙栈。
基线只是没有调用蓝牙 API，最终固件也不会链接未使用的蓝牙代码。

**ESP32-S3 只有 BLE，没有 Classic Bluetooth。** `BluetoothSerial` 使用 Classic
SPP，在 S3 上可以编译但链接会失败，不要使用。当前
`framework-arduinoespressif32 @ 2.0.14` 的预编译库只带 Bluedroid BLE，不带
NimBLE；请使用 Arduino core 自带的 `BLE` / `BLEDevice` 库。如果必须使用
NimBLE，需要换用带 NimBLE 的 Arduino core 或直接用 ESP-IDF 构建，不能只靠
`-DCONFIG_BT_NIMBLE_ENABLED=1` 切换。

WiFi：

```cpp
#include <WiFi.h>

WiFi.mode(WIFI_STA);
WiFi.begin("ssid", "password");
```

BLE：

```cpp
#include <BLEDevice.h>
#include <BLEServer.h>

BLEDevice::init("guachat");
BLEServer *server = BLEDevice::createServer();
```

启用前先确认：

- **天线**：模组是 `ESP32-S3-WROOM-1U`，属于外接天线版本。仓库只记录了 LoRa
  和 GPS 天线，没有记录 ESP32 的 2.4 GHz 天线；先确认真机 IPEX 天线已装好，
  否则 WiFi / BLE 距离会很短。
- **2.4 GHz 共存**：实测在 **LoRa 7 dBm** 下可以与 WiFi 同时工作；这是目前唯一
  验证过的并发条件。**LoRa 功率更高时，近距离有损坏 ESP32-S3 LNA 的风险**；
  固件只提示、不阻止，是否提高功率由你自行决定并承担风险。若同时使用，建议让
  LoRa 中心频率远离 WiFi 信道：至少避开 WiFi 的 20 MHz 占用带宽并留保护带，
  最终以丢包率和吞吐实测为准；做不到频率隔离时，建议分时工作。**默认 2405 MHz
  靠近 WiFi ch1（2412 MHz）；如果 WiFi 用 ch1，建议改到远离该信道的频率。**
  BLE 与 WiFi 同属 2.4 GHz，但 BLE 未做并发实测，按同样原则处理。
  当前 `radio_test_task` 每 500 ms 发送一次，可作为 7 dBm 并发测试负载；如果
  选择分时方案，再停掉它并让 SX1280 进入 standby。当前 BSP 还没有暴露
  standby/sleep 接口，需要时补一个简单的射频仲裁层。
- **电源与发热**：WiFi 峰值约 340 mA；LoRa 7 dBm 与 WiFi 并发已实测。高功率
  LoRa、WiFi 和音频功放同时满载时电流与发热都会上升，建议做功耗评估后再长期运行。
- **合规**：启用 WiFi / BLE 后，默认的“微功率豁免”假设不再成立，按第 3 节
  重新评估。

建议：

- 在**新分支**上做，不要污染基线；
- 在 `README` 或交付说明中明确写出“本固件启用了 WiFi / 蓝牙”；
- 不要同时保留“符合微功率豁免”的表述；
- 即使 7 dBm 下可以并发，也要做频率隔离、丢包率和吞吐实测，并重新评估功耗与发热。

## 5. 验证脚本的行为

`tools/validate.py` 会：

- **警告**：LoRa 频率超出 2402–2482 MHz、硬件上限超过 20 dBm，或推荐值高于
  已验证的 7 dBm；
- **警告**：检测到 `WiFi.h` / `esp_wifi` / `esp_now` / `WebServer` / `HTTPClient`
  等符号，提示“已启用无线功能，请自行确认合规性”；
- **不禁止**：不会因为出现 WiFi/蓝牙或修改射频参数而让构建失败。

这样既能让 Agent 知道风险，又不会阻止用户做自己的设备。

## 6. 报告要求

如果本次改动涉及射频或无线功能，交付报告必须包含：

```text
RF changes:
  - 频率 / 功率 / 天线 / 调制是否改动
  - 是否启用 WiFi / 蓝牙 / ESP-NOW
  - 是否与 WiFi / BLE 并发；LoRa 功率与频率间隔
  - 估算 EIRP
  - 合规责任声明：本固件为自用/学习用途，未取得 SRRC/CE/FCC 认证
```
